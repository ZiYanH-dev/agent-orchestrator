# 需求文档

> 版本：v0.1（初版）
> 对应代码状态：后端与前端核心链路已实现，动态编排与 HITL 为增量特性。

## 1. 产品定位

**agent-orchestrator** 是一个基于 LangGraph 的多 Agent 编排引擎，用于 RAG（检索增强生成）问答场景。用户上传文本资料（.txt / .md），系统自动解析、分块、向量化入库；用户提问时，四个 Agent 角色协作完成"问题拆解 → 文档检索 → 答案生成 → 质量质检"的闭环。

核心价值：**编排本身才是本体，检索只是被编排的一环**；回答有据可依、过程可观测、可人工干预。

## 2. 目标用户

| 用户 | 典型场景 |
| --- | --- |
| RAG 应用开发者 | 需要可视化多 Agent 协作流程（拆解 / 检索 / 生成 / 质检） |
| 多 Agent 方案验证者 | 对比规则路由与动态编排两种模式的行为差异 |
| 知识问答使用者 | 上传文本资料，获得基于资料的结构化回答 |

## 3. 核心用户故事

1. 作为用户，我想注册并登录，以便保存我的文档与运行记录。
2. 作为用户，我想上传一份 `.txt` / `.md` 资料，系统解析后我能在知识库中检索到它。
3. 作为用户，我想发起一次 Agent 问答，系统以确定性或动态模式完成多步推理。
4. 作为用户，我希望看到每一步的执行轨迹（哪个节点、耗时、重试），而不是黑盒答案。
5. 作为用户，当答案质检不通过时，我希望人工介入并决定采纳还是重写。
6. 作为用户，我想在旧会话继续追问，保持上下文连续。

## 4. 功能清单

### 4.1 账号（Auth）
- 注册（用户名 + 密码 + 可选邮箱）
- 登录获取 JWT（`Authorization: Bearer <token>`）
- 获取当前用户信息

### 4.2 文档管理（Documents）
- 上传文档（`.txt` / `.md`），自动：落盘 → 解析 → 分块 → 向量化入库
- 查看文档列表（分页、按当前用户隔离）
- 删除文档（同步删除分块、向量与本地文件）

### 4.3 会话管理（Chat Sessions）
- 创建会话、重命名、删除
- 查看会话历史消息（分页）

### 4.4 问答（Chat）
- 同步 RAG 问答：`POST /chat`，一次请求返回完整回答与来源
- 流式问答：`POST /chat/stream`，SSE 推送 `sources → token → done`
- 检索范围严格限定在"当前用户的文档"

### 4.5 Agent 编排（Agent Runs）
- 启动 Agent 运行：`POST /agent/runs`（确定性模式默认）
- 动态编排：`AGENT_ORCHESTRATION_MODE=dynamic` 时由 supervisor 模型逐步决策
- 流式运行：`POST /agent/runs/stream`，事件含节点轨迹与最终答案
- 人工介入恢复：`POST /agent/runs/resume`，`decision=accept/rewrite`
- 运行列表与详情（按 `session_id` 分组）

### 4.6 系统
- 健康检查 `/health`

## 5. 非功能性需求

| 维度 | 要求 |
| --- | --- |
| 数据安全 | 用户间数据隔离（文档 / 会话 / 运行均按 `user_id` 归属与过滤）；密码哈希存储 |
| 编排收敛 | 六层护栏保证图一定收敛：步数上限 / 目标白名单 / 前置状态校验 / 打转检测 / 工具调用上限 / 重试上限 |
| 可观测 | SSE 推送节点轨迹（`node_start` / `node_done`）、Agent 运行落库 `agent_runs` + `agent_steps` |
| 可扩展 | 双编排模式复用同一批节点，仅连线方式不同 |
| 可维护性 | 五层单向依赖 + 类型注解 + ruff / mypy(strict)；190 个单元测试 |
| 本地优先 | 无外部依赖即可跑通测试（SQLite 内存库 + FakeRedis）；LLM / Embedding 支持 OpenAI 兼容接口与本地 Ollama |

## 6. 范围与边界

**已实现**：账号、文档上传与向量化、会话、同步与流式 RAG 问答、双模式 Agent 编排、六层护栏、HITL 人工介入、checkpoint（memory / redis）、运行轨迹落库。

**规划中**：生产部署（Dockerfile 真实化、nginx、CI，见 `Problem/08`）、PDF / Word 解析（当前仅文本，见 `Problem/16`）、落盘文件回收（见 `Problem/17`）、分页稳定排序（见 `Problem/12`）。

**明确不做（本期）**：多用户协作共享知识库、模型微调、移动端原生 App。
