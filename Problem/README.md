# 问题清单

本目录记录 2026-09-22 对 agent-orchestrator 做启动、跑测试与代码审查时发现的全部问题。

编号 16、17 是后续整理项目文档、逐条核对上传链路时实测发现的，与前 15 项的处理建议一致。

## 怎么用这个目录

问题按**子系统**归档到 6 个文件，不再一题一文件。

| 文件 | 子系统 |
|------|--------|
| [backend-agent.md](backend-agent.md) | Agent 编排与鉴权（01-04、15.2） |
| [backend-documents.md](backend-documents.md) | 文档上传与回收链路（16、17） |
| [backend-core.md](backend-core.md) | 测试 / 配置 / 仓储 / 脚本（05、11-13、15.1、15.5） |
| [frontend.md](frontend.md) | 前端（09、10、15.3） |
| [infra.md](infra.md) | Makefile / Docker / 工程化（06-08、14、18、15.4） |

- 新增问题 → 判断属于哪个子系统，丢进对应文件，条目标题前标 `[OPEN]`。
- 修完 → 把 `[OPEN]` 改为 `[DONE]`，不搬文件，同步改条目内「状态」一行。
- 每条保留原有结构：现象、根因、证据、影响、建议改法、验证方式。
- 标题前的编号（01、02、15.1…）仅用于跨条目引用，不代表处理优先级。

## 严重级别定义

| 级别 | 含义 |
| --- | --- |
| 🔴 P0 | 安全漏洞或会导致运行失败，必须优先处理 |
| 🟠 P1 | 影响可维护性或上线安全，应在下一次迭代处理 |
| 🟡 P2 | 不影响当前功能，但会积累技术债 |
| ⚪ P3 | 规范一致性问题，随手可修 |
